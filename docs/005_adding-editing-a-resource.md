# Adding & Editing a Resource

This is the task you'll do most often. This page walks through it end to end. It assumes you've already picked a type (see **Choosing a Resource Type**).

## Creating a new resource

1. In the Studio's left-hand list, scroll to the resource types and click the type you want — e.g. **Articles**.
2. Click the **+** (create new) button in the **document list**.
3. You'll get a blank document with an empty **draft**. Nothing is live yet, and nothing is saved to the published site until you publish. Fill in the fields, then publish (see below).

To **edit** an existing resource, find it in the same list (use the search box at the top of the list to filter), open it, and make your changes. Editing creates a new draft on top of the published version until you publish again.

> **Tip**
>
> Many times in the Studio there are multiple ways to achieve the same task. For example, you can also create a new resource by selecting the **+** icon in the very top menu bar

## The field groups

A resource form is organised into tabs, called **groups**, along the top. You don't have to fill them in order, but this is roughly the order of importance:

### Resource Attributes

The core facts about the resource. Type-specific fields also live here — a Book's author/ISBN, a Podcast's Spotify and Apple links, and so on. These details (when added) will usually be used to enrich the listing on the website and improve the user experience.

### Classification

The **tags** that decide where this resource appears on the site. This is the editorially important part (see **Tagging & Classification**). In short: the more accurately you classify a resource, the more reliably it reaches the people it can help.

Note that **Audience Role** (bereaved / supporter / professional) is required here.

### Search & SEO

Fields relating to search within our website. Configuring these will enable a user to find a resource via our site search more reliably.

### Access Restrictions

Honesty about barriers, so visitors know whether there they may need to pay or register to access a resource

### AI

Settings that control the **AI Content Editor**.

## Validation: errors vs warnings

Sanity checks your input as you type:

- **Errors** (red) _block publishing_. A missing required field, a duplicate URL, or an ISBN of the wrong length are errors — you must fix them.
- **Warnings** (yellow) are _advice_, not blocks. An over-long title or description
  warns you but still lets you publish. Treat warnings as a nudge to reconsider,
  especially on titles and descriptions where brevity genuinely helps grieving
  visitors.

> **Warning**
>
> Sometimes errors and warnings only show at the document level - rather than next to the field that has the problem. If you have a document that wont publish, its likely that's what the problem is

## Saving, drafts, and publishing

Sanity saves your work **automatically and continuously** as a **draft** — there's no "save" button, and you won't lose work if you navigate away. But a draft is _not live_.

- **Publish** (the button at the bottom of the document) promotes your draft to the published version. Only published content is picked up when the site is built.
- **Draft** if a document has unpublished changes, the Studio shows it as having a draft.
- You can **discard** a draft to revert to the last published version.

> **Tip**
>
> Remember from **The Content Model**: publishing doesn't instantly change the live site — a build has to run first. See **How Content Reaches the Site**.

> **Tip**
>
> The document list shows the status of a document with colored dot indicators. A green dot indicates that document has a current published version. An amber dot indicates there is a "draft" version that has not yet been published. Both dots present together indicates (as you may guess) that there is a previously published version, as well as draft changes that are yet to be published

## A good default workflow

1. Choose the right **type**.
2. Fill in **Resource Attributes** — get the title, description, and URL right.
3. **Classify** it carefully (Classification tab).
4. Add **Search Aliases** if there are obvious terms people would search that aren't in the title/description.
5. Set any **Access Restrictions** honestly.
6. Re-read the description as if you were grieving and looking for help.
7. **Publish.**

## Editing safely

- **Changing a URL** replaces where the link points — make sure the new URL is still the same resource, or you may want a new resource instead.
- **Deleting a resource** removes it from every page it appeared on. If a resource has simply moved or gone stale, consider updating it rather than deleting.
- If you didn't create a document and its content surprises you, check with the team before overwriting or deleting it.
